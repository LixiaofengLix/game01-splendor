# UI U4 测试用例：入口与流程

> 机器能判断的部分已在开发时跑完，结论写在文末。你只需要做 U4-01、U4-02、U4-04 里
> “人工观察”的步骤；其余用例保留作回归。
> 命令里的 `$GODOT` = `/Applications/Godot.app/Contents/MacOS/Godot`，在仓库根目录运行。

## U4-01 主菜单 → 本地开局 → 牌桌 → 暂停 → 保存 → 退出 → 继续

- **前置条件**：无（第一次运行会自动创建 `user://saves/`）。
- **步骤**：
  1. `$GODOT --path . ui/app/app.tscn`
  2. 观察主菜单：左侧标题、说明、按钮列；右侧三张扇形卡、牌堆、贵族、筹码、吉祥物；
     没有“继续上一局”（首次运行）；“联网游戏”和“设置”是灰色的。
  3. 点【本地游戏】。在 02 里确认：座位 1 是“人类”并带“你”标签，座位 2 / 3 是“电脑 · 普通”；
     右侧规则摘要显示 3 人对应的“每色 5 枚 · 金 5 枚”“贵族 4 位”。
  4. 点【开始对局】。拿 3 种颜色各 1 枚并确认，等回合结束。
  5. 按 Esc（或点顶栏【菜单】）打开暂停：右栏有规则速查；点【保存】，确认牌桌顶部出现
     “已保存到「快速存档」”的 toast。
  6. 点【退出】→ 展开【确认退出】【取消】，点【确认退出】回到主菜单。
  7. 主菜单此时应出现橙色【继续上一局】，副标题类似“3 人 · 第 1 轮 · 刚刚”。点它。
  8. 观察牌桌恢复到刚才的座位、轮次、分数和宝石。
- **预期结果**：全程不需要调试界面；继续后的局面与退出前一致（自动存档在每回合结束时写）。
- **人工观察点**：
  - 主菜单右侧静物是否有元素互相遮挡（筹码 / 吉祥物 / 贵族）。
  - 02 的座位行在 3 人 / 4 人时是否对齐；难度分段只出现在电脑行。
  - 暂停菜单左栏按钮宽度一致；规则速查的数字与右侧面板一致。
  - 继续后顶栏“第 N 轮”和当前行动者是否正确。

## U4-02 同屏换人遮挡（2 位以上人类）

- **前置条件**：无。
- **步骤**：
  1. `$GODOT --path . ui/app/app.tscn` →【本地游戏】。
  2. 点常用组合【4 人同屏】（或把座位 2 改成“人类”，并打开“换人时遮挡”）。
  3. 点【开始对局】。应立刻出现整屏遮挡：两位吉祥物、“同屏 · 换人”、“轮到 小明”、
     一张“刚才没有其他动作”的摘要卡、【我是小明，开始我的回合】。
  4. 点按钮或按 Enter。牌桌显示座位 1 的私密信息。
  5. 拿 3 种宝石并确认。下一回合应再次出现遮挡，这次指向座位 2，摘要卡写座位 1 刚才的动作。
  6. 回到 02（重新开一局），关掉“换人时遮挡”再开 4 人局：不应再出现遮挡。
- **预期结果**：遮挡期间看不到下一位的宝石 / 盲抽；点按钮后才渲染；电脑回合不出现遮挡。
- **人工观察点**：遮挡是不是完全不透明；标题名字与按钮名字是否一致；摘要是否看得懂。

## U4-03 读档列表 / 坏存档（回归）

- **前置条件**：先按 U4-01 产生一份自动存档或快速存档。
- **步骤**：
  1. 主菜单 →【读取存档】。左侧应至少有“自动存档 / 快速存档”，右侧默认选中第一份。
  2. 逐项点选：详情里的玩家、种子、动作步数、轮次、“✓ 可以完整重放”应该随选中变化。
  3. 选中一份预设局面（文件名 `preset...` 或调试界面留下的 json）：删除按钮应为禁用，
     详情应提示“快照存档只有「继续」，没有「看回放」”。
  4. 关闭游戏，在存档目录里造三个坏文件再打开【读取存档】：
     ```bash
     SAVE_DIR="$HOME/Library/Application Support/Godot/app_userdata/Splendor/saves"
     printf '{ 这不是 JSON' > "$SAVE_DIR/corrupt.json"
     printf '{"schema_version": 99, "kind": "replay", "player_count": 2}' > "$SAVE_DIR/too_new.json"
     printf '{"schema_version": 1, "kind": "mystery", "player_count": 2}' > "$SAVE_DIR/unknown.json"
     ```
     列表里应分别出现“无法读取 / 文件损坏”“无法读取 / 版本太新”“无法读取 / 不认识的类型”，
     游戏不崩；选中时没有【继续这局】。
  5. 选中自己的快速存档，点【删除】，确认二次确认后从列表消失。
  6. 测完删除三个坏文件：
     ```bash
     rm -f "$SAVE_DIR/corrupt.json" "$SAVE_DIR/too_new.json" "$SAVE_DIR/unknown.json"
     ```
- **预期结果**：坏存档留在列表里并写明原因；只读存档不能删；删除有二次确认。

## U4-04 异常弹窗（回归，可选）

- **21 数据错误**：正常流程下不会出现。机器测试用假错误列表检查了标题、逐条错误、复制和退出按钮；
  如果你要亲眼看，临时把 `data/rules.json` 的 `max_tokens` 改成 0，启动 `ui/app/app.tscn`，
  应直接出现“游戏数据有问题，没法开局”，改回后恢复。
- **22 存档错误**：按 U4-03 的坏文件步骤，选中坏文件不会出现 22；22 用于“列表里看起来能读、
  实际载入失败”的回放（校验失败）。机器测试覆盖了版本太新 / 损坏 / 校验失败三种文案。

## 开发时已跑过的机器验证（结论）

- `tests/ui_smoke.tscn`：**1198 项全部通过**。测试输出里的
