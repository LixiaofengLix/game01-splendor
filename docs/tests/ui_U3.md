`ui_smoke` 的 U3 部分覆盖：

- 隐私：自己的盲抽从缓存补上、别人的盲抽隐藏、观战隐藏、公开预留保留。
- 真实会话：点筹码拿同色 2 枚 / 三种颜色；可点颜色与 `legal_actions()` 一一对应；
  所有购买 / 预留 / 盲抽合法动作都有入口；支付预览与 `card_purchased.paid` 逐色一致。
- `token_limit` 场景：拿宝石超过上限 → 弃宝石弹窗 → 选够才能确认 → 弃后持币回到 10、日志合并。
- `two_nobles` 场景：回合末进入选贵族 → 两位候选 → 选一位 → 贵族进入面板。
- `endgame` 场景：购买计分卡触发终局 → 座位 1 走完 → 结算弹窗与胜者。
- 非法动作：顶条出现“这一步没成功”，不上日志。
- 电脑回合：所有动作入口锁定，银行筹码不可点，浮层隐藏。
- `quick_start`：设置界面结构、3 人局开局、座位类型。

## 人工试玩（需要你）

先建目录并启动：

```bash
mkdir -p /tmp/splendor_ui
$GODOT --path . ui/dev/quick_start.tscn
```

| 选 2 人、普通、开始 | 直接进入牌桌，座位 1 是你，座位 2 是电脑 |

### U3-09 拿宝石的手感（重点）

| 步骤 | 预期结果 |
|---|---|
| 点银行里一枚筹码 | 筹码出现橙框和“+1”角标；顶条写“再选 2 种不同颜色…”；托盘写“拿 白 · 1 / 10” |
| 同一颜色连点两次 | 第二次变成 2 枚（角标 +2），顶条写“同色 2 枚（X银行剩 N 枚）” |
| 再点第三种颜色 | 顶条写“三种不同颜色各 1 枚”，托盘和银行下方的【确认】同时可用 |
| 点【取消】或按 Esc | 选择清空，顶条回到操作提示 |
| 拿宝石前已经 9 枚，拿 3 枚 | 顶条提前写“拿后 12 枚，确认后需要弃 2 枚” |
| 确认拿取 | 筹码回到我的面板；轮到的对手面板出现橙框；日志出现“你拿了 …” |

**观察点**：点筹码的响应是否跟手；+N 角标是否清楚；托盘和银行下方的确认是否同步；
确认后是否立刻轮到下一位（电脑会先转圈再出手）。

### U3-10 买卡 / 预留 / 盲抽（重点）

| 步骤 | 预期结果 |
|---|---|
| 点一张场面卡 | 卡上移 4px、出现橙框和 ▼；右侧 272 宽浮层显示标题、支付预览、买后变化和两个按钮 |
| 看浮层 | 三行“折扣 / 宝石 / 金币”（用不到的写“无”）；下面的“买后：宝石 a → b，X 折扣 c → c+1，分数 s → s+p” |
| 买得起 | 浮层标签“可买”，【购买】可用；按 Enter 或点【购买】完成 |
| 买不起 | 标签“还差 N”，购买禁用；“需要 / 已有”列出缺的颜色和金币可抵的枚数 |
| 预留 | 【预留 · +1 金】（金币没了写“金币已空”）；按 R 或点按钮完成；卡进入我的预留区 |
| 预留已满 | 预留按钮禁用，下面写“预留已满 3 张” |
| 点牌堆 | 浮层只有“盲抽预留 · +1 金”和说明；预留后我的面板出现牌背，轮到自己时翻正面 |
| 点我的预留卡 | 浮层只有【购买】 |

**观察点**：支付预览和实际扣掉的宝石是否一致（日志 / 我的面板数字）；浮层是否挡住不该挡的东西；
预留后的牌背 / 正面切换是否符合预期（见下方“已知问题”）。

## 已知问题（不阻塞 U3）

1. **刚盲抽的牌要等下一回合才翻正面**：IR-01（按座位取视图）落地前的缓存方案只记得“自己看到过的”
   预留卡；盲抽事件里没有卡 id，下一次视图又属于下一位玩家。因此在电脑回合里，这张新牌先画牌背。
2. **同屏多人类没有换人遮挡**：U3 的临时入口固定只有座位 1 是人类。U4 的 09 屏接上后再验证。
3. **HUD 的“规则”按钮没有反应，“菜单”按钮直接返回开局设置**：正式暂停菜单 / 规则速查在 U4。
4. **没有动效**：筹码飞行、卡滑走、补牌翻开、贵族来访动画都在 U5；U3 只有光晕和日志。
5. **完整日志（L）还没做**：日志面板只显示最近几条；完整的日志浮层在 U4。
6. 截图 / 试玩时的 `WARNING: ... RIDs ... leaked` 是 Godot 强制退出时的资源提示，不影响结果。
