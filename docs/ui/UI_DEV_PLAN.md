# 正式 UI 开发计划

> 依据：`docs/ui-mockup-v4.html`（V4 像素风，23 屏 + 交互规则 + 接口对照）。
> 对接面：`docs/UI_INTEGRATION.md`（逻辑侧维护）+ 本目录的 `BRIDGE_AND_REQUESTS.md`（UI 侧维护）。

## 0. 目标与范围

- 用正式 UI 替换 `debug_ui/`：主菜单 → 开局设置 → 牌桌 → 结算 / 回放，以及存读档、设置、
  大模型与联网界面、异常提示。规则、对局流程、存档格式都不改。
- 像素风：深色木纹牌桌 + 羊皮纸面板、9 宫格像素边框、像素金币筹码、点阵宝石与吉祥物、像素字体。
- 窗口基准 1280×800（`project.godot` 已是 `canvas_items` + `expand`）。
- **不在本计划内**：深色模式、小于 1280×800 的布局、扩展规则、正式音效素材（只留播放钩子）。

## 1. 并行开发约定（互不干扰）

UI 线和逻辑线（阶段 5 大模型、6 联网、7 收尾）同时推进。约定如下。

### 1.1 目录归属

| 目录 / 文件 | 归属 | UI 线能否修改 |
|---|---|---|
| `ui/`（新建） | UI 线 | 可以 |
| `docs/ui/`、`docs/tests/ui_UN.md` | UI 线 | 可以 |
| `tests/ui_*.gd/.tscn`（新建） | UI 线 | 可以 |
| `core/` `game/` `ai/` `llm/` `net/` `autoload/` | 逻辑线 | **不可以**。需要新接口就登记 IR（见 `BRIDGE_AND_REQUESTS.md` 第 4 节） |
| `data/*.json`、`data/ai/`、`data/llm/` | 逻辑线 | **不可以** |
| `debug_ui/` | 逻辑线（调试工具） | **不可以**；U9 之前一直保留，作为对照和兜底 |
| `tests/` 里已有的自检脚本 | 逻辑线 | **不可以** |

### 1.2 共享文件

| 文件 | 规则 |
|---|---|
| `project.godot` | U0–U8 **不改**。主场景切换、导出过滤留到 U9，和阶段 7 一起改。纹理过滤、快捷键都在 `ui/` 代码里设置（见第 3 节），用不着改项目设置 |
| `CLAUDE.md` | 只在“常用命令”里追加 UI 线的命令，并在 U0 补一条“UI 线约定见 `docs/ui/`”。改约定要先和逻辑线对齐 |
| `docs/PROGRESS.md` | UI 线不写。UI 进度写 `docs/ui/UI_PROGRESS.md`，`PROGRESS.md` 的“当前状态”里只留一行指向它 |
| `docs/UI_INTEGRATION.md` | 逻辑线维护。IR 落地后由逻辑线更新，UI 线只读 |
| `docs/README.md` | 双方都可以追加条目，不改别人的行 |

### 1.3 接口冻结与变更

- UI 只依赖 `docs/UI_INTEGRATION.md` 列出的公开接口，以及已落地的 IR 接口。
  不调用下划线开头的私有函数，不读 `GameState` 内部字段（评审时 grep：`ui/` 下不能出现 `_state`、`GameState.new`、`._`）。
- **所有对逻辑层的调用都集中在 `ui/bridge/`**。屏幕和零件只认桥接层，不直接碰 `GameController` / `Rules`。
  这样逻辑侧改接口时，UI 侧只需要改一个目录。
- 逻辑线改动 `UI_INTEGRATION.md` 里的任何签名或信号时，在 `docs/PROGRESS.md` 的偏差里写明，并跑一次 `tests/ui_smoke.tscn`。
- UI 线需要的新能力一律登记为 IR，写清：用途、建议签名、UI 侧的临时替代方案。**不等 IR**：
  先用假后端或临时替代开发，IR 落地后在桥接层换成真实实现。

### 1.4 假后端

阶段 5 / 6 的界面（大模型、联网）现在没有逻辑实现。桥接层提供 `FakeBackend`，按夹具脚本发出
和真实后端相同形态的信号与视图。UI 先对着它把界面和交互做完，逻辑阶段完成后换成 `LiveBackend`。
细节见 `BRIDGE_AND_REQUESTS.md` 第 2–3 节。

### 1.5 测试与提交

- UI 改动必跑：`tests/ui_smoke.tscn`（U2 起），外加 `tests/data_report.tscn`（确认数据层没被意外影响）。
- 逻辑线改动 `game/` 后，除了已有的自检，也跑一次 `tests/ui_smoke.tscn`（防止接口破坏）。
- 提交信息前缀 `UI-Un：`，每个 U 阶段验收后提交一次。UI 线只提交第 1.1 节里自己的目录，
  不把逻辑线未提交的改动带进 UI 提交。
- 建议 U0 开始前，先把阶段 4 的现有改动提交掉，避免两条线的未提交改动混在一起。

## 2. 架构

```
 screens/（各屏） ──读写──▶ bridge/TableSession ──▶ LiveBackend ──▶ GameController / Rules（只读视图）
       │                        │                  └▶ FakeBackend ──▶ dev/fixtures/*.json
       ▼                        ▼
 components/（零件）    common/ViewMath（从视图算分数、折扣、缺口、支付预览）
       ▼
 theme/（Theme、调色板、字体）+ assets/pixel/（工具生成的 PNG）
```

- **视图是唯一真相**：每次 `view_updated` 都按视图整桌重画（重画是幂等的，零件可以复用节点）。
  动效只是叠在上面的表现层，可以被跳过、被打断，不影响状态。
- **能点什么只看合法动作**：可点状态全部由 `legal_actions()` 推出，界面不自己判断“看起来合法”。
- **规则数值从 `RulesConfig` 读**：15 分、10 枚、3 张、拿 2 枚的阈值 4，都不写死在界面里。

## 3. 目录结构（`ui/`）

```
ui/
├── README.md
├── app/            # 入口场景 app.tscn：屏幕路由、弹窗层、toast 层、全局快捷键（运行时注册 InputMap）
├── theme/          # pixel_theme.tres、palette.gd（颜色常量）、fonts/（字体 + OFL 许可证）
├── assets/
│   ├── pixel/      # 工具生成的 PNG：9 宫格边框、金币、宝石、吉祥物（不要手改）
│   └── sfx/        # 音效（后期，先留空）
├── tools/          # build_pixel_assets.gd/.tscn：从点阵定义生成 assets/pixel/*.png
├── bridge/         # 唯一调用逻辑层的地方：table_session、live_backend、fake_backend、
│                   # replay_source、save_store（user://saves/）、ui_settings
├── common/         # view_math.gd（纯函数，从视图 + CardCatalog 算显示用的数）、text.gd（文案拼接）
├── components/     # 零件：gem_chip、bonus_tile、cost_pill、dev_card、deck_pile、noble_tile、bank_column、
│                   # opponent_panel、my_panel、log_panel、event_strip、turn_pill、segmented、pixel_switch、
│                   # card_popover、modal_frame、toast、notice_card
├── screens/        # main_menu、local_setup、save_browser、table/、hotseat_cover、modals/、replay、
│                   # settings/、net/、errors/
└── dev/            # gallery.tscn（零件全状态陈列）、fixtures/（假后端与渲染用的视图 JSON）、capture.tscn（截图）
```

约定（和 `CLAUDE.md` 一致，另加 UI 线专属的）：

- 类名统一加 `Ui` 前缀（`UiDevCard`、`UiTableScreen`），避免和 `debug_ui/` 的 `BoardScreen` 等撞名。
- 场景和脚本放在一起，文件名 snake_case。场景能静态搭的就用 `.tscn` 搭（方便在编辑器里看效果），
  列表类的内容（卡、筹码、日志行）用代码实例化。
- `ui/app/app.tscn` 根节点设 `texture_filter = TEXTURE_FILTER_NEAREST`（子节点继承），不改项目设置。
- 快捷键在 `ui/app/` 启动时用 `InputMap.add_action()` 注册，动作名统一用 `spl_` 前缀（`spl_confirm` 等），
  不和 Godot 内置的 `ui_accept` / `ui_cancel` 冲突。
- 运行：`/Applications/Godot.app/Contents/MacOS/Godot --path . ui/app/app.tscn`（U9 前主场景仍是调试界面）。

## 4. 阶段划分

优先级：**看得清 → 能玩 → 流程完整 → 好看 → 新功能界面 → 替换收尾**。
先做零件和静态牌桌（视觉问题最早暴露），再接真实对局（U3 就能试玩），之后再补流程、动效和阶段 5 / 6 的界面。

| 阶段 | 目标 | 依赖 | 对应样张 |
|---|---|---|---|
| U0 | 工程骨架、字体、像素贴图 | 无 | 零件（素材部分） |
| U1 | 零件库 + 陈列场景 | U0 | 零件 |
| U2 | 牌桌按任意视图静态渲染 | U1 | 04、07、08 |
| U3 | 牌桌可交互，接真实对局，能人机打完一局 | U2 | 04–08、10–12 |
| U4 | 主菜单到结算的完整流程、存读档、同屏 | U3、IR-04 | 01–03、09、13、21、22 |
| U5 | 事件动效与反馈 | U3 | 交互规则“反馈”一条 |
| U6 | 回放 | U4、IR-03 | 14 |
| U7 | 设置 + 大模型界面 | U4；接真等阶段 5 | 15–17 |
| U8 | 联网界面 | U4；接真等阶段 6 | 18–20、23 |
| U9 | 替换调试界面、导出 | U3–U8、阶段 7 | 全部 |

和逻辑线的时间关系：U0–U5 只依赖已完成的阶段 1–4，现在就能开始；U6 依赖 IR-03；
U7 / U8 先用假后端做完界面，“接真”分别跟在阶段 5 / 6 之后；U9 和阶段 7 合并验收。

### 阶段 U0：工程骨架与素材

目标：`ui/` 能启动一个空壳，所有像素素材和字体就位，以后的零件只管用。

1. 建 `ui/` 目录树（第 3 节）和各文件夹 `README.md`；`CLAUDE.md` 常用命令追加 UI 启动命令，并加一句“UI 线约定见 `docs/ui/`”；
   创建 `docs/ui/UI_PROGRESS.md`，`docs/PROGRESS.md` 的“当前状态”里加一行指向它。
2. 字体：下载 Fusion Pixel 12px Proportional 简中、Press Start 2P，连同 `OFL.txt` 放进 `ui/theme/fonts/`；
   按 `VISUAL_SPEC.md` 第 3 节设置导入参数（关抗锯齿、关 hinting、关子像素）。
3. `ui/tools/build_pixel_assets.gd/.tscn`：把样张页尾脚本里的点阵定义移植过来，用 `Image` 画出并存 PNG 到 `ui/assets/pixel/`：
   - 9 宫格边框：小框 5 色、大框 2 色（直接 2× 尺寸）；
   - 金币：6 色 × 满 / 空 = 12 张；
   - 宝石形状：6 色 × 彩色 / 单色 = 12 张；
   - 吉祥物：4 个座位 + 眯眼 = 5 张；
   - 牌背斜纹平铺图、木纹桌面平铺图、羊皮纸棋盘格平铺图。
   脚本结束时自检张数和尺寸，不对就 `quit(1)`。
4. `ui/theme/palette.gd`：`VISUAL_SPEC.md` 第 2 节的全部颜色常量。
5. `ui/theme/pixel_theme.tres` 初版：默认字体、字号变体（12 / 24 / 48，数字 8 / 16 / 32）、按钮 / 面板 / 标签的 `StyleBoxTexture`。
6. `ui/app/app.tscn`：根节点 Nearest 过滤、挂主题、运行时注册快捷键（`spl_` 前缀）、空的屏幕路由和弹窗层；
   启动时检查 `DataRegistry.is_valid()`，失败先简单打印（21 屏在 U4 做）。
7. `docs/tests/ui_U0.md`。

验收重点：生成工具可以重复跑、结果一致；`app.tscn` headless 启动退出码 0；`tests/data_report.tscn` 仍然通过。
需要你参与：无（全部机器验证）。

### 阶段 U1：零件库

目标：`VISUAL_SPEC.md` 第 5–6 节的每个零件都能单独实例化，并且所有状态在一个陈列场景里看得到。

1. 通用控件：按钮（5 种变体 × sm / 默认 / lg × 正常 / 悬停 / 按下 / 禁用）、菜单大按钮、分段、开关、输入框、标签（6 种配色）、
   kbd、进度条、转圈、列表行、弹窗框、toast、提示卡。
2. 宝石类：`UiGemChip`（4 种尺寸 × 正常 / 空心 / 已选 +N / 待弃 −N / 无数字）、`UiBonusTile`（各尺寸 × 0 / 非 0）、`UiCostPill`。
3. 卡牌类：`UiDevCard`（市场 / 迷你 × 普通 / 可买 / 差 N + 悬停缺口条 / 选中 + ▼ 光标 / 光晕 / 对手买得起头像 / 空位 / 牌背 / 我的盲抽标签）、
   `UiDeckPile`（有牌 / 已空 / 选中）、`UiNobleTile`（市场 / 大号 × 普通 / 选中）、`UiCardRef`。
4. 每个零件只接收“显示数据”（颜色、数字、card_id + `CardCatalog`），不认识视图字典——视图到零件的转换在 U2 的牌桌里做。
5. `ui/dev/gallery.tscn`：照样张“设计零件”一节排版，所有状态并排；`ui/dev/capture.tscn` 可以把陈列场景截成 PNG。
6. 缩放评估：把陈列场景分别在 1280×800、1440×900、1920×1200 下截图，比较第 6 节第 1 条的两种缩放方案。
7. `docs/tests/ui_U1.md`：给出截图命令和逐项观察点。

验收重点：零件状态齐全；12px 像素字清晰不糊；颜色 + 形状在灰度截图下也能分辨。
需要你参与：对照样张看截图（像素清晰度、颜色、字号）；**拍板缩放方案**。

### 阶段 U2：牌桌静态渲染

目标：给一份视图字典，牌桌能完整、正确地画出来，2 / 3 / 4 人都不溢出。暂不响应点击。

1. `ui/common/view_math.gd`：分数、折扣、持币总数、缺口、支付预览、买得起的座位、轮数、终局还剩谁（`BRIDGE_AND_REQUESTS.md` 1.4）。
2. `ui/screens/table/` 的牌桌场景，按 `SCREENS.md` 的牌桌几何搭：顶栏 + 回合胶囊、贵族列、三级市场（牌堆 + 卡位）、银行、
   我的面板（顶条 / 身份 / 资源 / 预留）、对手面板（6 列网格、进度条、预留标记）、日志（条数随对手数变化）。
3. 牌桌只有一个入口 `render(view, me_seat, session_info)`，幂等，重复调用不泄漏节点。
4. 观战 / 回放布局：没有“我”时右栏列出全部玩家，底部留给播放条（先放占位）。
5. 夹具：`ui/dev/build_fixtures.tscn`（按种子跑局、存 `current_view()`）+ 照样张手写 G3 / G4 局面；
   至少覆盖 04、07、08、牌堆已空、银行见底、2 人 / 4 人。
6. `tests/ui_smoke.gd/.tscn` 第一版：逐个夹具渲染，核对卡牌 id、银行 / 玩家数字、分数和视图一致，盲抽隐私不泄露。
7. `docs/tests/ui_U2.md`。

验收重点：所有夹具渲染无报错、数字与视图一致；4 人局右栏不溢出；三级在最上面。
需要你参与：截图对照样张 04、07、08。

### 阶段 U3：牌桌交互 + 接真实对局

目标：人机 2–4 人局能用鼠标完整打完。这是 UI 线的**第一次试玩**。

1. `ui/bridge/`：`UiTableSession` + `LiveBackend`（接 `GameController`，见 `BRIDGE_AND_REQUESTS.md` 1.5），
   隐私处理（别人的盲抽、电脑自己的盲抽画牌背；IR-01 前用缓存补我自己的盲抽）。
2. 拿宝石状态机（`INTERACTION.md` 第 2 节）：银行筹码点选、托盘、银行下方确认 / 取消、超上限提示、1–5 / Enter / Esc。
3. 选卡与浮层（第 3 节）：场面卡、牌堆、我的预留卡；支付预览、预留按钮文案、Enter / R / Esc；“购买前确认”开关先写死为开。
4. 回合内弹窗（第 4 节）：弃宝石（一次选够、逐个提交、中途被拒重开）、选贵族、结算（含破同分说明、`stalled` 文案）。
5. 锁定与反馈：电脑回合全锁、回合胶囊、对手面板 `hot` 框、我的面板顶条各状态（第 6 节）、相关卡光晕 1.5 秒、日志文案（第 7 节，先不做飞行动效）。
6. `action_failed` 处理（第 10 节）。
7. 临时入口：`ui/dev/quick_start.tscn`，选人数和电脑难度直接开局（U4 的正式设置界面出来后删掉）。
8. `ui_smoke` 扩充：模拟点击走拿宝石 / 购买 / 预留 / 盲抽；在 `token_limit`、`two_nobles` 预设局面里走弃宝石和选贵族；
   可点入口和合法动作一一对应；支付预览与 `card_purchased.paid` 交叉校验；电脑回合入口全部禁用。
9. `docs/tests/ui_U3.md`。

验收重点：随机人机对局能打完；非法操作点不了；界面状态与规则一致。
需要你参与：**试玩**——人机 2 / 3 / 4 人局各打一局，重点感受拿宝石和买卡的手感、电脑出手能不能看明白。

### 阶段 U4：入口与流程

目标：从主菜单开始，不碰调试界面就能完成“开局 → 打完 → 再来一局 / 存档 → 继续”。

1. 21 数据加载失败弹窗（启动时）。
2. 01 主菜单（含桌面静物装饰、继续上一局、联网入口禁用）。
3. 02 本地开局设置：座位行（名字、类型、难度）、加减座位、常用组合、人数 / 种子 / 规则只读标签、同屏开关；删掉 U3 的临时入口。
4. 09 同屏换人遮挡（`INTERACTION.md` 第 5 节的出现条件）。
5. 13 暂停菜单 + 规则速查（数值从 `RulesConfig` 拼）+ 保存 toast + 退出二次确认。
6. `UiSaveStore`：自动存档（每回合结束）、快速存档、结束转存、带 `ui_meta`；“继续上一局”。
7. 03 读档列表 + 详情；22 存档无法读取（三类原因）。“看回放”按钮先隐藏（U6 打开）。
8. IR-04 落地前：继续和电脑的对局时恢复成全人类座位，并显示提示。
9. 12 结算的【再来一局】（同设置、新种子）、【回主菜单】、【保存回放】。
10. `ui_smoke` 扩充：主菜单 → 设置 → 开局 → 自动存档 → 回主菜单 → 继续上一局，状态指纹一致；坏存档出现在列表里并写明原因。
11. `docs/tests/ui_U4.md`。

验收重点：完整流程不需要调试界面；存档 / 读档后状态一致；坏存档不会让界面崩。
需要你参与：从主菜单完整走一遍；同屏 2 个人类时的遮挡体验。

### 阶段 U5：动效与反馈

目标：电脑和别人出手时，看得清发生了什么，但不拖慢节奏。

1. 动效队列：先事件后视图、积压快进、可跳过（`INTERACTION.md` 第 7 节）。

## 6. 风险与待决策

1. **像素风遇上非整数缩放**：`canvas_items` + `expand` 在 1440×900 这类窗口下缩放系数不是整数，
   像素会大小不一。U1 用截图对比两种方案再定：
   (a) 保持分数缩放 + Nearest（最省事，会有轻微像素抖动）；
   (b) `window/stretch/scale_mode = "integer"`（像素完美，但会留边，而且要改 `project.godot`，只能在 U9 落地）。
2. **中文像素字体体积**：Fusion Pixel 12px 简中字体有数 MB。如果导出包体积是问题，U9 再考虑子集化。
3. **样张里的贵族名字**：`nobles.json` 没有名字。界面一律用位置（“左边这位”）或要求（“白 4 蓝 4 的贵族”）指代，
   不显示 `N-06` 这类 id（IR-07 是可选项）。
4. **玩家昵称只存在 UI 层**：引擎只有座位号。名字随 `ui_meta` 写进存档（IR-06）；联网时由大厅分配（阶段 6）。
5. **“电脑思考延迟”设置**：现在延迟写在 `data/ai/*.json` 里，界面改不了。IR-05 落地前，设置页不显示这一项。
