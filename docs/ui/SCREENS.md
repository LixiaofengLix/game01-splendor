# 各屏说明

> 编号和样张一致（01–23）。每屏写：布局、数据来源、交互、边界情况、依赖。
> “桥接层”指 `ui/bridge/TableSession` 等（接口见 `BRIDGE_AND_REQUESTS.md`）；“视图”指 `to_dict(viewer_seat)` 的字典。
> 交互细节（状态机、动效、快捷键）统一写在 `INTERACTION.md`，这里只写每屏特有的部分。

## 界面流程

```
01 主菜单 ─┬─ 继续上一局 ───────────────────────────▶ 04 牌桌
           ├─ 本地游戏 → 02 本地开局设置 ────────────▶ 04 牌桌 ─▶ 12 结算 ─┬─ 再来一局（同设置，新种子）→ 04
           ├─ 读取存档 → 03 读档 ─┬─ 继续 ─────────────▶ 04         ├─ 看回放 → 14
           │                     └─ 看回放 ───────────▶ 14          └─ 回主菜单 → 01
           ├─ 联网游戏 → 18 建房 / 加入 → 19 大厅 ────▶ 04（联网） ⇢ 20 掉线接管 / 23 断线重连
           ├─ 设置 → 15 / 16
           └─ 退出
04 牌桌内：05 拿宝石 / 06 买·预留 → 10 弃宝石（持币超限）→ 11 选贵族（同时满足 ≥ 2 位）→ 下一位
          → 07 电脑回合 / 09 换人遮挡 / 17 大模型思考；Esc → 13 暂停（存档 / 读档 / 规则速查 / 设置 / 退出）
启动时数据校验失败 → 21；读档失败 → 22
```

18–20、23 是阶段 6 的界面，16、17 是阶段 5 的界面，逻辑没完成前用假后端开发，主菜单入口禁用（“开发中”）。

## 牌桌布局（04–08、10–14、17、20 共用）

1280×800 基准下的几何（逻辑像素）：

```
┌────────────────────────────── 顶栏 44 ──────────────────────────────┐
├─ 牌桌（木纹）内边距 14 ──────────────────────────────────────────────┤
│ ┌── 左栏 906 ───────────────────────────────────┐ 16 ┌─ 右栏 330 ─┐ │
│ │ ┌ 市场 高 470 ──────────────────────────────┐ │    │ 提示卡（可选）│ │
│ │ │ 贵族列 100 │14│ 牌堆 96 │10│ 卡 128 ×4（间距 10）│14│ 银行 100 │ │ │ 对手面板 ×1–3 │ │
│ │ │            │  │ 三行，每行 150，行距 10            │  │          │ │ │ （间距 8）    │ │
│ │ └────────────────────────────────────────────┘ │    │              │ │
│ │ 12                                             │    │ 日志（占满剩余，│ │
│ │ ┌ 我的面板 高 246 ──────────────────────────┐ │    │  最少 130）   │ │
│ │ └────────────────────────────────────────────┘ │    │              │ │
│ └────────────────────────────────────────────────┘    └──────────────┘ │
└──────────────────────────────────────────────────────────────────────┘
```

- 市场从上到下是三级、二级、一级（三级在最上面）。每行：牌堆 + 4 个卡位（卡位数从 `RulesConfig.board_slots_per_level` 读）。
- 贵族列的贵族数 = 视图里 `nobles` 的数量，竖排平分高度。
- 市场实际宽 876，在左栏里左对齐，剩余空间留给浮层。
- 窗口比 1280 宽：多出来的宽度给右栏（右栏最宽 420），再多就整体居中；比 800 高：多出来的高度先给日志，
  市场卡牌放大留到 U9 之后再说（样张提到但没画）。
- 视图里没有“我”时（全电脑观战、回放），右栏列出全部玩家，底部换成回放播放条或观战条。

**“我”是谁**：同屏时 = 当前行动的人类座位；轮到电脑 / 远程 / 大模型时 = 最近一个行动过的本机人类座位；
本机没有人类座位 = 观战（没有“我”）。规则见 `INTERACTION.md` 第 5 节。

## 01 主菜单

- **布局**：左半区：基础版 · 2–4 人的眉标、48 号标题“璀璨宝石”、一段玩法说明（胜利分从 `RulesConfig` 读）、
  菜单按钮列（宽 360）；右半区：桌面静物装饰（扇形三张卡、牌堆、一位贵族、几摞筹码、座位 1 的吉祥物），
  只用零件拼，不另画插图；左下角版本号。
- **按钮**：
  - 继续上一局（accent，**唯一的橙色按钮**）：只在存在“进行中”的自动存档时出现；副文字“3 人 · 第 9 轮 · 10 分钟前”（取自 `ui_meta`）。
  - 本地游戏（dark）：进 02。
  - 联网游戏（ghost）：阶段 6 前禁用，副文字改成“开发中”。
  - 读取存档 / 设置 / 退出（quiet，一排三个）。
- **数据**：`SaveStore.autosave_summary()`。
- **边界**：数据校验失败时不进主菜单，直接显示 21。

## 02 本地开局设置

- **布局**：顶栏“‹ 主菜单”+ 标题“本地游戏”。左列：座位面板（feature）+ 常用组合；右列（380）：对局面板、同屏面板、
  “开始对局”（accent、lg）。
- **座位行**：序号（从 1 开始）+ 吉祥物 40 + 名字输入框（宽 150）+ 类型分段【人类 / 电脑 / 大模型】+ 类型专属选项 + “移除”。
  - 人类：第一个人类座位旁显示 dark 标签“你”和说明“同屏时轮到你才显示你的盲抽牌”。
  - 电脑：难度分段【简单 / 普通 / 困难】→ 座位类型 `bot_easy` / `bot_normal` / `bot_hard`。
  - 大模型：配置档下拉 + 说明“失败时由「困难电脑」兜底”。阶段 5 前这一段禁用（悬停提示“大模型座位将在后续版本开放”）。
  - “＋ 加一位玩家（最多 4 人）”和“移除”联动人数；人数下限 / 上限从 `RulesConfig.supported_player_counts()` 读。
- **默认值**：座位 1 人类（名字取设置里的默认昵称）、其余普通电脑（和调试界面一致）；默认名字按座位取吉祥物名（薄荷、紫晶、橘子）。
- **常用组合**（点一下填好座位，再微调）：单挑电脑（你 vs 困难）、标准 3 人（你 + 2 普通，默认选中样式）、
  4 人同屏（全人类，打开换人遮挡）、电脑对战（2 个电脑，观战）。
- **对局面板**：人数分段（和座位数同步）；种子输入（留空随机）+“随机”按钮；说明“同一个种子开局完全一致”；
  “本局规则”只读标签：胜利分、持币上限、预留上限、“每色 N 枚 · 金 N”、“贵族 N 位”——随人数变化，
  全部来自 `RulesConfig`（`gems_per_color_for()`、`gold_count`、`nobles_for()`）。
- **同屏面板**：换人时遮挡（开关，有 2 个以上人类座位时才生效）；电脑思考延迟分段（IR-05 落地前隐藏）。
- **开始**：`TableSession.start_local({count, seed, seats: [{name, type}], hotseat_cover})`；失败时在按钮上方显示原因。
- **边界**：全是电脑 → 按钮文字改“开始观战”；名字为空 → 用默认名；名字最长 8 个字。

## 03 读档

- **布局**：左列存档列表（白底），右列（440）详情。
- **列表行**：吉祥物（座位 1 的头像，或胜者的头像）+ 名称 + 状态标签 + 一行摘要 + 类型标签 + 时间。
  - 名称：自动存档 / 快速存档 / “10-14 · 小明获胜”（已结束）/ 预设局面名。
  - 状态标签：进行中（orange）、已结束（mint）、无法读取（red，写明原因）。
  - 类型标签：回放（purple，种子 + 动作，可以重放）/ 快照（orange）。
- **详情**：标题 + 保存时间 + “每回合结束自动覆盖”（自动存档才有）；玩家卡（头像、名字、类型、分数）；
  键值表：种子、动作（“74 步 · 第 9 轮 · 轮到小明”）、完整性（“✓ 可以完整重放”，选中时才去校验）；
  按钮：继续这局（accent）、从头看回放（ghost，快照没有）、删除（quiet，二次确认）。
  说明：“快照存档只有‘继续’，没有‘看回放’——它没有种子和动作序列。”
- **数据**：`SaveStore.list()` 扫 `user://saves/*.json`，用 `SaveFile.kind_of()` 判断类型；
  摘要来自存档里的 `ui_meta`（IR-06），没有 `ui_meta` 的文件（调试界面存的 `board_quick.json` 等）只显示人数和步数，玩家名用“座位 N”。
- **读不了的存档留在列表里并写明原因**，不静默消失：版本太新（`schema_version` 大于支持的版本）、文件损坏（JSON 解析失败）、不认识的类型。
- **依赖**：继续 = `load_replay` / `load_snapshot`，恢复电脑座位要 IR-04；“看回放”要 IR-03。

## 04 牌桌 · 轮到我

- 顶栏：“3 人局 · 第 9 轮”；胶囊“轮到你 · 小明”；右侧“规则”“菜单 Esc”。
- 市场卡牌对“我”标出：**可买**（深绿框 + “可买”）、**差 N**（悬停看缺哪几色、金币能抵几枚）；
  卡右上的小头像 = 那个对手现在就买得起（提醒要不要抢 / 预留卡位）。

- 对手面板、日志（最近 7 条）。

## 05 牌桌 · 拿宝石选择中

- 选中的筹码橙框 + “+1 / +2”角标；银行底部出现“确认拿取 / 取消”（鼠标不用横跨屏幕）。
- 顶条托盘同步：已选的筹码、“拿 白 蓝 黑”/“拿 2 枚蓝”、“拿后 8 / 10”、取消、确认。
- 顶条左侧提示随选择变化（“再选 1 种不同颜色；同一颜色再点一次 = 拿 2 枚”/“三种不同颜色各 1 枚”/“同色 2 枚（蓝色银行剩 5 枚）”）；
  拿完会超过上限时提前说“拿后 12 枚，确认后需要弃 2 枚”。
- Enter 确认、Esc 取消。状态机见 `INTERACTION.md` 第 2 节。

## 06 牌桌 · 选中卡牌 → 购买 / 预留

- 点场面卡：卡选中（橙框、上移、▼ 光标），右侧出浮层（`VISUAL_SPEC.md` 6.11）。
  - 买得起：标签“可买”、自动支付预览（先折扣、再同色宝石、最后金币，和规则引擎一致）、
    “买后：宝石 6 → 3，蓝色折扣 2 → 3，分数 3 → 5”、按钮【购买】【预留 · +1 金】、提示“Enter 购买 · R 预留 · Esc 取消”。
  - 买不起：标签“还差 N”、“需要 / 已有”两行、购买禁用。
  - 预留按钮文案：银行有金币 → “预留 · +1 金”；金币没了 → “预留（金币已空）”；预留满 → 禁用并写“预留已满 3 张”；
    `reserve_takes_gold` 关掉时只写“预留”。
- 点牌堆：浮层只有“盲抽预留 · +1 金”，说明“看不到是哪张，抽到后只有你自己能看见”。
- 点我的预留卡：浮层只有购买。
- 顶条：“已选中 二级蓝卡 —— 在浮层里购买或预留，点空白处取消”。选卡会清掉已选的宝石（反过来也一样）。

## 07 牌桌 · 电脑回合

- 胶囊白底：“[头像] 紫晶 · 电脑 · 普通 [转圈] 思考中…”；正在行动的对手面板用 `hot` 框 + 橙色侧标 + “思考中”标签。
- **所有卡和筹码不可点**（悬停“差 N”提示仍然可以看）；能开暂停菜单、能看完整日志。
- 上一步的结果写进我的面板顶条（事件态）：“[头像] 薄荷 预留了 [二级红 · 1 分]　拿到 1 枚金币 · 现在轮到紫晶　刚刚”；
  相关卡光晕 1.5 秒。**市场上方不放任何浮层。**
- 电脑的弃宝石 / 选贵族不弹窗，只写日志和顶条。

## 08 牌桌 · 4 人局 + 终局触发

- 右栏三个对手面板 + 日志只露 4 条（“全部记录 L”）。
- 有人到胜利分：顶栏常驻 orange 标签“终局轮 · 还剩 N 人”；我的面板顶条：“小明 到 15 分了！终局轮：薄荷、紫晶、橘子各还有一回合，之后结算”，
  右侧“终局轮”。不弹会挡住三级牌的 toast。
- N 的算法：`turn_counts` 小于最大值的座位数（触发者自己的回合已经结束）。

## 09 同屏换人遮挡

- 整屏实色盖住（不透明，`BG` 棋盘格），中间：下一位的吉祥物（上一位的半透明在旁边）、dark 标签“同屏 · 换人”、
  “轮到 **小明**”（名字反白）、说明“其他人请先别看屏幕。点下面的按钮后才会显示你的宝石和预留牌（包括盲抽的那张）。”、
  一张小卡总结上一位人类之后发生了什么（“紫晶 刚才购买了 [二级红 · 1 分]，并获得了贵族”）、
  按钮“我是小明，开始我的回合”（accent、lg）、小字“只在有 2 个以上人类座位时出现；可在开局设置里关掉”。

## 10 弃宝石

- 牌桌上盖遮罩，弹窗（560）：标题“宝石太多了”+ red 标签“12 / 10”；说明“回合结束时最多持有 10 枚。点筹码选出要还给银行的 2 枚，金币也可以弃。”；
  一排 6 枚 `lg` 筹码（下面写颜色名），点一下 = 弃 1 枚（角标“−1”、数字减 1），弃到 0 不能再点；
  汇总条：“弃掉 [绿][红] 绿 1 · 红 1　弃后 10 / 10”；按钮【重选】【确认弃掉 2 枚】（选够之前禁用）。
- **不能取消、不能关**（规则强制）；Esc 无效。胶囊写“小明 · 弃宝石”，顶条“持币超过上限，先弃回银行”。
- 提交方式见 `INTERACTION.md` 第 4 节。

## 11 选贵族

- 弹窗（560，居中排版）：紫色吉祥物、标题“两位贵族都想来拜访你”（3 位时“三位”）、
  说明“你的折扣同时满足两位，但每回合只能请一位。另一位留在场上，以后仍可能来访。”；
  候选贵族用 200×170 的大牌并排，点选（黑框暖底 + 橙框）；下面一条“你的折扣 [5 个折扣块]”方便核对；
  按钮“请右边这位来访（+3 分）”（按位置指代，不露 id；没选时“先选一位贵族”并禁用）。
- 不能取消。候选来自视图的 `pending_nobles`。

## 12 结算

- 弹窗（720）：头像 64 + dark 标签“对局结束 · 第 27 轮” + 标题“小明 获胜”（并列时“小明、薄荷 并列获胜”）+ 右侧其他人的头像。
- 名次表：名次（第 1 名用 `ORANGE`）、头像、名字、类型标签、“卡 12 · 贵族 2”、分数。并列胜者同为第 1。
- **破同分说明卡**（dark，只在最高分并列时出现）：“小明和薄荷同为 16 分，按规则比较购买的卡牌数：小明 12 张 < 薄荷 14 张，小明胜。”
  卡牌数也相同时：“……卡牌数也相同，两人并列获胜。”
- 底部：左“用时 38 分钟 · 结束原因：达到 15 分”；右【回主菜单】【看回放】【保存回放】【再来一局】。
  `finished_reason == "stalled"` 时标题改成“对局僵持，按分数结算”，结束原因写“对局无法继续推进”
  （“没人有合法动作”和“回合数到上限”两种情况引擎都记为 `stalled`，界面不区分）。
- **数据**：`game_ended` 的 winners / scores + 视图（卡数、贵族数）；用时由界面计时（读档继续的局从 `ui_meta.elapsed_sec` 接着算）。
- 结算弹窗在事件动效播完之后再出现。快照来源的局（`can_save_replay()` 为 false）不显示“看回放 / 保存回放”。

## 13 暂停菜单 + 规则速查

- Esc 或顶栏“菜单”打开；弹窗（720）左右两栏。
- 左（230）：“暂停”、【继续游戏】（accent）、【保存】、【读取存档】、【设置】；底部分隔线下：“退出会丢掉自上次保存以来的进度”
  +【确认退出】（danger、sm）【取消】——点“退出”先展开这两个按钮（二次确认）。开了自动存档时文案改成“退出后可从‘继续上一局’回来”。
- 右：规则速查（数值全部从 `RulesConfig` 拼）：拿宝石 / 预留 / 购买 / 回合末 / 终局 五条；快捷键：1–5 选宝石、Enter 确认、Esc 取消 / 暂停、L 日志。
- 保存成功：牌桌顶部暖色 toast“已保存到「快速存档」　可从主菜单 → 读取存档 继续”。
- 本机对局暂停时冻结电脑思考计时（桥接层暂停）；**联网局里“暂停”不会停住别人**，只是打开菜单。
- 弃宝石 / 选贵族弹窗打开时也能开暂停（叠在上面），关掉后回到原弹窗。

## 14 回放

- 用同一张牌桌；没有“我”，右栏列出全部玩家；顶栏胶囊“回放 · 自动存档 · 第 37 / 74 步”，右侧【从这里接着玩】【退出回放】。
- 底部播放条（替换我的面板，高 246）：
  - 当前步说明：头像 + “第 37 步 · 第 13 轮” + “薄荷 盲抽预留了三级牌堆顶”。
  - 视角分段：每个玩家名 +“全部公开”。视角决定能不能看到某人的盲抽牌（`viewer_seat`）。“全部公开”也不显示牌堆顺序。
  - 时间轴：每一步一格、按座位着色，已播放的实色、未播放的灰；当前步加高 + 橙框；点格子跳转。
  - 控制：⏮ 开头、‹ 上一步、▶ 播放 / ⏸ 暂停（accent、lg）、下一步 ›、结尾 ⏭；速度 0.5× / 1× / 2×。
- 日志按步编号（“#37”），当前步高亮。

## 22 存档无法读取

- 异常弹窗：薄荷吉祥物、标题“这个存档读不了”、feature 卡：原因标签 + 一句人话 + 说明。
  - 重放校验失败（指纹不一致 / 第 N 步执行失败）：“重放到第 37 步时，局面和存档记录的不一样。”+“通常是卡表或规则改过数值。存档文件没有动，换回原来的数据就能读。”
    按钮【返回列表】【读到第 36 步为止】（IR-03 前不显示后者）。
  - 版本太新：“由更新版本的游戏保存，升级后才能读取。”
  - 文件损坏：“文件内容不完整或不是存档。”
- 原因来自 `load_replay` / `load_snapshot` 的 `errors`；界面把它归成上面三类，原文放在可展开的“详细信息”里。
